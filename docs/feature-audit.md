# Feature audit — 24 September 2026

Audited the local checkout implementation at commit `160ae99` and the public site at https://www.iyayusufspantry.com. The storefront is largely functional, but the site is **not ready to accept real customer orders**. Passing prototype tests does not mean the corresponding business integration is complete.

## Fix progress after this audit

The original findings below are retained as the baseline. Follow-up implementation on the same date:

- Fixed missed clicks by keeping reveal-animation hit targets stationary. All six repeats of the previously failing desktop scenarios passed with normal motion, and the complete existing suite passed **104/104** locally.
- Registered the Contentful publish/unpublish/delete webhook. An authenticated request for an existing published entry returned **200, revalidated: true** on the public site.
- Reduced the existing Stripe test destination from 244 events to the four supported Checkout Session events. Its signing-secret match and the public checkout flag still require Vercel configuration.
- Added protected `/owner` operations for actual persisted sandbox orders, fulfillment, stock edits, and contact messages. Stock changes protect reservations and reject stale edits; fulfillment requires a paid order. Owner APIs check authorization independently and return no-store responses.
- Added persistent contact submissions, newsletter consent/confirmation/unsubscribe, confirmed-subscriber CSV export, an email outbox with leased/idempotent retries, and request limits for forms and checkout. The protected maintenance handler reconciles pending payments and dispatches configured mail; a scheduler is still required.
- Created the operations schema and applied additive sandbox migrations. Generated local form/maintenance secrets without printing them. No real owner identity, sender credentials, shipping charges, or tax rules were invented.
- Passed **9 payment backend tests**, **9 operations backend tests**, **6 payment browser checks**, and **8 operations browser checks**. New checks cover access denial, duplicate contact requests, newsletter consent/expiry/unsubscribe, email retry leases, stale stock edits, and fulfillment restrictions. The local Stripe expiration/idempotency smoke check also passed after adding request limits.
- Completed actual Clerk development registration, OTP verification, sign-out, and password sign-in using reserved test addresses. A verified test owner read a real saved contact submission; a regular authenticated account received 403. The exact temporary accounts/message were cleaned up. An additional run encountered a transient database connection timeout; a later run passed, and no residual test contact remained.
- Production build and lint passed. Email provider transport is mocked in automated tests; no real email has been sent by this work.
- A fresh Stripe hosted test-card purchase passed after the changes: the signed webhook persisted payment, deducted sample stock, and the confirmation page showed success. A prior attempt returned a temporary checkout error during a database connectivity interruption; the later run passed. The automated suites total **136 passing checks**, excluding the targeted repeats and external-provider acceptance checks.

See [Store operations](operations.md) for configuration, commands, and remaining launch dependencies. Local source changes and database setup do not by themselves enable features on Vercel. Public owner/form activation needs an owner allowlist and relevant feature flags; outbound email needs a provider/verified sender; public sandbox payment needs the matching Dashboard secret and checkout flag. Live sales remain unsupported pending approved business rules and separate live integration work.

## Desktop interaction defect

The deployed suite initially passed **102 of 104 checks**. Failures were in `tests/prototype.spec.ts` at the filtering/search scenario and the Buy now navigation scenario.

Three repeated runs of each affected desktop scenario produced **4 failures out of 6**: filtering/reset failed three times, and Buy now failed once. Separate browser probes reproduced a first click doing nothing followed by a successful second click, without a JavaScript page error.

Running the same six checks with the browser's reduced-motion preference enabled passed **6 of 6**. This strongly implicates the reveal animation in `components/animated-main.tsx`: focusing a control cancels and restores its containing animation, which can move the control during a pointer interaction. The precise event sequence still needs a focused fix and regression test. No source fix was made during this audit, and the reduced-motion result does not replace the failing default-motion result.
