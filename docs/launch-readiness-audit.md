## Test issue corrected

The first Clerk acceptance run failed because automation submitted the OTP before the verification preparation request completed. `scripts/operations/auth-smoke.mts` now observes a successful POST to `prepare_verification` before entering the code, following [Clerk's signup testing guidance](https://clerk.com/docs/guides/development/testing/playwright/test-sign-up-flows). The complete acceptance run then passed; lint and formatting of the changed script passed. The first failure log and screenshot are retained locally. No application authentication code was changed.

## Remaining launch blockers and gaps

1. **Outdated public privacy copy.** `/privacy` currently claims contact, checkout and newsletter forms do not send or save entered details. Contact/newsletter now persist data and payment checkout sends data to Stripe. Correct that factual statement and finalize the policy to describe actual processing. Terms/shipping pages and the site footer also still identify themselves as prototype content.
2. **Live payments are not implemented.** The current configuration and event handler deliberately reject live keys/events. Switching environment variables alone will not enable real sales. A separate live checkout, inventory and webhook rollout needs end-to-end acceptance.
3. **Shipping and tax are unfinished.** US-only delivery and USD are enforced in sandbox. Orders currently charge zero shipping/tax; automatic tax is disabled. The proposed $6.99 shipping/free over $60 defaults are documented, not implemented. Business ship-from details, tax configuration and fulfillment coverage remain needed.
4. **Products and policies need owner validation.** Current prices, stock, product/allergen information and delivery estimates are samples or drafts. Database consistency tests cannot establish physical stock or policy accuracy.
5. **Authentication and search indexing remain in prelaunch mode.** Public pages load Clerk's development instance and emit `noindex, nofollow`. Configure production authentication and review indexing at launch.
6. **Email has only simulated delivery evidence here.** Custom-domain sending and newsletter state transitions passed. The sending-only Resend credential cannot inspect domain status/delivery logs; dashboard verification and an actual inbox delivery check remain needed. Live purchase receipts were not tested or enabled; sandbox order emails remain off.
7. **Automatic recovery timing is not yet observed.** The manual maintenance invocation passed, but a configured schedule is not evidence that an automatic run has executed. Check the next scheduled workflow execution and monitor failures.
